MY PRIVATE SPACE

Help

Encrypted file and folder storage

Import files and folders into the vault. My Private Space stores encrypted content under opaque IDs, while the navigation tree shows the original names after you unlock the vault. Select a file to preview supported images, PDFs, text, audio, and video.

Multiple vaults

Create separate vaults for different purposes using the same main password. After authentication, one registered vault opens directly; multiple vaults show a selector. Switch without re-entering the password, or lock the workspace. The current vault label appears in the navigation panel.

Recoverable deletion

Delete moves items into Deleted Items, including a folder's contents, so you can restore them. Permanent deletion is available from Deleted Items. Removing a vault from the registered list is different: it preserves the encrypted directory and its contents.

Item locks

Files and folders can have an additional password. A locked folder hides its children until unlocked, and locked file content cannot be previewed. Keep a secure record of these passwords; there is no password recovery service.

Vault folders, conversion, and backups

Choose an empty directory for a new vault. A valid existing vault can be registered again without changing IDs or contents. An ordinary non-empty folder requires explicit conversion confirmation; files are staged, encrypted, and verified before committing, with originals kept recoverable until then. Optionally, each vault can let My Private Space manage folder visibility. When enabled, supported systems hide the folder on registration and make it visible on unregistration; when disabled (including for older registry entries without this flag), folder visibility is left unchanged. Native visibility management is supported on macOS and Windows; Linux is left unchanged rather than renaming directories. Hiding is cosmetic, not a security measure. Hiding is cosmetic, not a security measure. Back up both vault directories and config.me together. Restore a vault by locating its encrypted directory and registering it with the same main password.

Main password, lockout, and inactivity

Changing the main password updates all registered vaults as one staged transaction; secondary passwords remain independent. Three consecutive failed main-password attempts trigger a five-minute lockout persisted in state.me. An unlocked vault automatically locks after five minutes without activity, including across tabs.

Storage prefixes and security limitations

Each new vault has an immutable prefix for new physical IDs. Existing IDs remain unchanged. state.me uses simple reversible obfuscation and Base64, not encryption or tamper protection. The main password transformation is deterministic and is not a password-based key derivation function. Keep backups and do not expose the local server to a network.

Privacy and local use

This app is designed to run on your computer through its local address. Do not expose the server to your network. Browser-based copy/save deterrents are not a guarantee against screenshots or access by someone who controls the computer.

The main password uses the deterministic 32-byte transformation described in the README. Review the security notes and maintain independent backups before storing irreplaceable data.
